# 架构约束模板

> 记录系统架构层面的硬性约束，供代码审查时对照检查。

## 使用方法

审查代码时，对照本文件中的架构约束，判断代码是否违反架构规范。

---

## 服务架构约束

| 约束 | 说明 | 严重程度 |
|-----|------|---------|
| （示例）所有接口必须通过网关访问 | 禁止直连后端服务 | P0 |
| （示例）禁止跨服务直接调用数据库 | 服务间只能通过 API 通信 | P0 |
| （示例）禁止服务间循环依赖 | 依赖关系必须是有向无环图 | P0 |

## 数据库约束

| 约束 | 说明 | 严重程度 |
|-----|------|---------|
| （示例）敏感字段必须加密存储 | 手机号、身份证、银行卡等 | P0 |
| （示例）禁止 SELECT * | 必须明确列出需要的字段 | P1 |
| （示例）大表查询必须带索引 | 查询条件必须走索引 | P0 |

## 缓存约束

| 约束 | 说明 | 严重程度 |
|-----|------|---------|
| （示例）缓存 key 必须带业务前缀 | 格式：`业务:模块:id` | P1 |
| （示例）缓存必须设置过期时间 | 防止内存泄漏 | P1 |
| （示例）禁止缓存敏感数据 | 敏感数据不进缓存 | P0 |

## 日志约束

| 约束 | 说明 | 严重程度 |
|-----|------|---------|
| （示例）日志格式统一用 JSON | 便于日志平台解析 | P1 |
| （示例）禁止在日志中打印敏感信息 | 密码、token、身份证等 | P0 |
| （示例）异常日志必须包含堆栈 | 便于问题排查 | P1 |

## 接口约束

| 约束 | 说明 | 严重程度 |
|-----|------|---------|
| （示例）接口必须有版本号 | URL 或 Header 中携带 | P1 |
| （示例）接口必须有幂等性设计 | 防止重复提交 | P0 |
| （示例）接口必须有权限校验 | 禁止未授权访问 | P0 |

## 填写规范

1. **约束**：简短描述架构约束
2. **说明**：详细解释约束内容
3. **严重程度**：P0（必须遵守）/ P1（强烈建议）/ P2（可选）

## 维护说明

- 架构调整时同步更新
- 新增架构约束时及时更新
- 约束变更时需评估影响范围
